# Zicci

飲食チェーンのアルバイト採用で、面接日程の調整を効率化するWebアプリです。
店舗のシフト表から面接可能な時間を自動で作り、応募者は公開ページから面接日時を予約できます。

## 技術構成

| 役割 | 技術 |
|---|---|
| 画面・サーバー | Next.js 16（App Router）＋ TypeScript |
| デザイン | Tailwind CSS 4 |
| データベース | Supabase（PostgreSQL）※無料プラン |
| 公開 | Vercel ※無料プラン（Hobby） |
| シフト画像の読み取り | Claude API（Claude Haiku 5.5・任意） |

## フォルダ構成

```
src/app/                  画面（ページ）
src/app/admin/            店舗側の管理画面（スタッフ・シフト・面接枠・設定）
src/app/admin/actions.ts  保存・変更の処理（Server Actions）
src/lib/slots/generate.ts 面接枠の自動生成ロジック（テストあり）
src/lib/supabase/         データベース接続
supabase/migrations/      データベースの設計図（テーブル定義）
supabase/seed.sql         デモ用データ
```

## セットアップ手順

### 1. Supabase（データベース）を用意する

1. https://supabase.com で無料アカウントを作り、「New project」でプロジェクトを作成します
   - Region は **Northeast Asia (Tokyo)** を選びます
   - Database Password は控えておきます（今回のアプリでは使いませんが、管理用に必要です）
2. 左メニューの **SQL Editor** を開き、次のファイルを順番に貼り付けて「Run」を押します
   1. `supabase/migrations/20261117000000_init.sql`（テーブル作成）
   2. `supabase/migrations/20261117010000_regenerate_slots.sql`（面接枠の作り直し処理）
   3. `supabase/migrations/20261118000000_create_reservation.sql`（予約の受付処理）
   4. `supabase/migrations/20261119000000_interview_guide.sql`（面接の進め方）
   5. `supabase/migrations/20261120000000_reservation_progress.sql`（面接後の進み具合）
   6. `supabase/seed.sql`（デモ店舗データ）

   > 2〜6 は何回実行しても大丈夫です。途中まで実行済みなら、続きから実行してください。
3. **Project Settings** から次の2つを控えます
   - **Data API → Project URL** … `SUPABASE_URL`
   - **API Keys → Secret key**（`sb_secret_` で始まるもの）… `SUPABASE_SECRET_KEY`
     （画面が古い場合は `service_role` キーでも動きます）

> ⚠️ Secret key は「何でもできる鍵」です。GitHub やチャットに貼らないでください。

### 2. 手元で動かす（任意）

```bash
cp .env.example .env.local   # 作成した .env.local に上の2つの値を書く
npm install
npm run dev                  # http://localhost:3000 を開く
```

トップページ下部の「システムの状態」が **データベース接続OK** になれば成功です。
「店舗の管理画面をひらく」から管理画面（`/admin`）に入れます。

```bash
npm test                     # 面接枠の生成ロジックのテスト
```

### 3. Vercel で公開する

1. https://vercel.com で GitHub アカウントを使って無料登録します
2. 「Add New… → Project」で `Zicci` リポジトリを選んで Import します
3. **Environment Variables** に次の3つを追加します
   - `SUPABASE_URL` / `SUPABASE_SECRET_KEY`（Supabase の値）
   - `ADMIN_PASSWORD`（管理画面のパスワード。4文字以上。自分で決める）
   - `ANTHROPIC_API_KEY`（任意。シフト表のAI読み取りを使う場合）
4. 「Deploy」を押すと公開URLが発行されます

## 開発の進め方

| フェーズ | 内容 | 状態 |
|---|---|---|
| P0 | 初期設定・テーブル作成・公開 | ✅ |
| P1 | 店舗設定・シフト手入力・面接枠の自動生成 | ✅ |
| P2 | 応募者の予約ページ・予約一覧・管理画面のパスワード | ✅ |
| P3 | シフト表の写真から入力（AI読み取り：Claude Haiku 5.5） | ✅ |
| P4 | ログイン・店舗ごとのデータ分離 | |

## 管理画面の使い方（P1）

1. **スタッフ**：スタッフを追加し、面接を担当できる人を選ぶ（複数可）
2. **シフト**：週を選んで、面接担当の勤務時間を入力・修正する
3. **設定**：面接の長さ（30/45/60分）、出勤直後・退勤直前の除外時間、繁忙・休憩時間を設定する
4. **面接枠**：「面接枠を作り直す」で自動生成 → 内容を確認 → 「公開する」
   - 枠をタップすると「受け付けない」に切り替わる
   - 作り直しても、予約済みの枠は消えない（その時間を避けて枠を作る）

## シフト表の写真から入力（P3）

- 管理画面「シフト」→「シフト表の写真から入力する」（`/admin/import`）
- ① 週を選んで写真を撮る／選ぶ → ② 「誰が面接できますか？」で面接担当を選ぶ（新しい人も追加可）
  → ③ 写真を画面上部に表示したまま、面接担当の1週間の勤務を入力 → 確認して登録
- 写真はサーバーに保存せず、端末の中だけで表示します
- 登録すると、選んだ人のその週のシフトが置き換わります。面接担当から外した人のシフトはそのまま残ります
- **AI読み取り**（任意）：環境変数 `ANTHROPIC_API_KEY` を設定すると、①に「AIで読み取る」ボタンが出ます
  - モデルは Claude Haiku 5.5（`src/lib/ai/shift-reader.ts`）。写真は端末で縮小（長い辺1600px）してから送ります
  - 読み取った値は②③にあらかじめ入り、**点線**で表示されます。人が修正すると実線になり、登録時に
    「AI読み取り（source=ai）」か「手入力（manual）」かが記録されます
  - クレジットの使いすぎ防止：管理画面にログインした人だけ、1時間に20回まで（接続元ごと）
  - 費用の目安：1枚あたり1円未満。Claude Console で月の利用上限を設定しておくと安心です
- **イベントのデモ用モード**：環境変数 `SHIFT_READER_DEMO=1` を設定すると、APIキーがなくても「AIで読み取る」が使え、
  どの写真を送っても `src/lib/ai/demo-result.ts` に決めておいたシフトが（数秒待ってから）入ります
  - デモで使うシフト表の画像は、`demo-result.ts` の内容に合わせて作ってください（曜日で決めているので、どの週でも使えます）
  - ⚠️ **イベントが終わったら、必ず `SHIFT_READER_DEMO` を削除して Redeploy してください。**
    オンのままだと、本物のシフト表を撮っても決めておいたシフトが入ってしまいます

## 面接の進め方（質問フロー）

飲食店では面接できる人が店長・社員に限られがちなので、**質問の流れを決めておき、アルバイトでも面接できる**ようにします。

- 編集：管理画面「スタッフ」→「面接の進め方を作る」（`/admin/guide`）
  - 「質問」と「伝えること（あいさつ・説明）」を順番に並べる。各項目に確認ポイント・回答の選択肢を設定できる
  - 飲食店のアルバイト面接向けのひな形（13項目）から始められる。並べ替え・削除可、最大40項目
- 実施：予約カレンダーの「面接を始める」（`/admin/guide/run?r=予約ID`）で、1項目ずつ大きく表示して進める
  - 今は流れを表示するだけで、回答やメモは保存しない

## 面接後の進み具合とアフターサービス

予約から結果までを4つのマイルストーンで示します：**①予約完了 → ②面接 → ③選考中 → ④結果のお知らせ**

- **応募者**：予約完了画面の「応募状況のページ」（`/r/demo/s/専用の値`。推測できないURL）で進み具合を確認
  - 選考中は「〇月〇日までに結果をお知らせします」と表示
  - 採用：入店案内（初出勤の日時・持ち物・集合場所など）／見送り：お礼のメッセージ
  - 面接の開始前なら、自分で「日時を変更する」「面接を辞退する」ができる（枠はすぐ空く）
- **店舗**：予約カレンダーで段階を進める
  - 面接画面の「面接を終える」または「面接済みにする」で選考中へ。結果連絡の期限＝面接日＋設定の日数
  - ホームに「結果の連絡を待っている人」を期限の近い順に表示（今日・明日・期限切れは赤）
  - 「採用」「見送り」を押すと、応募者のページにすぐ反映。採用した人には初出勤の日時を入れる
  - 入店案内・お礼の文・結果連絡までの日数は「設定」→「面接後の案内」で編集
- メールやSMSの自動送信はしません（応募者はページで確認。店舗は必要に応じて電話）

## 応募者の予約（P2）

- 予約ページ：`/r/demo`（管理画面の「設定」にURLとコピーボタンがあります）
- 応募者は「日付 → 時間 → お名前・電話番号（メールは任意）」で予約します
- 予約できるのは、公開中・未予約・担当者がいる枠で、開始1時間前まで、3週間先までです
- 担当者は、その枠に対応できる人のうち、その日の予約が少ない人に自動で割り当てます
- 予約は管理画面の「ホーム」にカレンダーで表示されます。日付をタップすると、その日の予約が時間順に並びます（電話をかける・取り消すボタン付き）

## セキュリティの方針

- 管理画面（`/admin`）は、環境変数 `ADMIN_PASSWORD` のパスワードでログインした人だけが使えます
  - `ADMIN_PASSWORD` が未設定（または4文字未満）のときは、誰もログインできません
  - 同じ接続元から5回続けて間違えると、10分間ログインできなくなります（短いパスワードの総当たり対策）
  - 試作では短いパスワードでも動きますが、実際の応募者の情報を扱う前に、推測されにくい長めのものに変えてください
  - パスワードを変えると、ログイン中の人も全員ログアウトされます
  - 店舗ごとのアカウント（P4）ができるまでの簡易的な仕組みです
- 応募者のページには、他の応募者の氏名・連絡先や担当者名は一切表示しません

- すべてのテーブルで RLS（行レベルセキュリティ）を有効にしています。ポリシーを作っていないため、ブラウザから直接データベースを読み書きすることはできません
- データベースの操作は、すべてサーバー側（Secret key を持つ Next.js のサーバー処理）で行います
- 重複予約は、データベースの制約で防いでいます
  - `reservations.slot_id` を UNIQUE にしているので、1つの枠に予約は1件までしか入りません
  - `interview_slots` に EXCLUDE 制約をかけているので、同じ店舗で時間が重なる枠は作れません
